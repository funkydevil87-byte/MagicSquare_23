## MagicSquare_23 — Cursor Agent(에이전트) 문서 구성 보고서

작성 목적: `.cursor/agents/*.md`에 전문 역할별 에이전트를 정의하고, 공통 안전 규칙을 모든 에이전트 프롬프트에 일관되게 적용한 결과를 기록한다.

---

### 1. 생성된 에이전트 파일 목록

아래 파일을 새로 생성했다.

- `.cursor/agents/code-reviewer.md`
- `.cursor/agents/performance-optimization-engineer.md`
- `.cursor/agents/ux-designer.md`
- `.cursor/agents/product-manager.md`
- `.cursor/agents/code-bug-analyzer.md`
- `.cursor/agents/multi-agent-orchestrator.md`

---

### 2. 각 에이전트 역할/책임 요약

- `code-reviewer`
  - 변경된 코드를 중심으로 버그/규칙 준수/성능 개선점을 점검하는 전문 코드 품질 리뷰어
  - Severity 기준과 코멘트 출력 포맷을 포함

- `performance-optimization-engineer`
  - CPU/메모리/I/O/DB/네트워크/렌더링/알고리즘 병목을 **측정 기반**으로 진단하고 최적화 전략을 제안
  - “측정 계획 → 원인/영향 → 전략 → 코드 개선안 → 예상 향상 → 부작용” 흐름을 강제

- `ux-designer`
  - 사용자 동선/버튼 강조/폼 UX/내비게이션/에러 메시지/접근성/반응형 관점에서 UI/UX 개선안을 제안
  - 응답 포맷(5단계)과 UX 체크리스트 포함

- `product-manager`
  - 제품 목표/요구사항 정의, PRD 구성, MVP 우선순위/일정/마일스톤/KPI를 구조화
  - PRD 작성 가이드와 응답 포맷(8단계) 포함

- `code-bug-analyzer`
  - 전체 코드 기반으로 버그/구조 문제/잠재 오류를 근거 중심으로 식별하고 P0~P3 우선순위를 정리
  - 재현 조건/영향/수정 제안/검증 방법을 포함하는 출력 포맷 포함

- `multi-agent-orchestrator`
  - 단계형 협업 시스템: (1) `code-bug-analyzer` → (2) `performance-optimization-engineer` → (3) `ux-designer`
  - 단계별 결과 연결, 변경 요약, 실행 가능 상태 유지, 백업/복원 규칙을 관리

---

### 3. 공통 안전 규칙의 전 에이전트 적용

요청된 “공통 Agent 안전 규칙”을 모든 에이전트 프롬프트의 맨 아래에 `## 공통 안전 규칙` 섹션으로 추가했다.

포함 규칙:

- 작업 전 현재 파일 구조와 관련 파일을 먼저 확인한다.
- 변경 전 어떤 파일을 수정할지 먼저 요약한다.
- 사용자의 명시적 승인 없이 파일 삭제, 대량 이동, Git push, 배포, DB 변경을 하지 않는다.
- 변경 후에는 수정 파일 목록, 변경 이유, 실행한 테스트 명령, 결과를 보고한다.
- 추측으로 수정하지 말고, 근거가 부족하면 “확인 필요”라고 표시한다.
- 보안 정보, API Key, 토큰, 비밀번호를 출력하거나 커밋하지 않는다.

---

### 4. 비고(운영 가이드)

- 에이전트 문서는 “프롬프트 재사용성”을 위해 **역할/원칙/체크리스트/출력 포맷**을 포함하도록 구성했다.
- 추후 에이전트 추가 시에도 동일한 공통 안전 규칙 섹션을 문서 하단에 포함하는 것을 권장한다.
