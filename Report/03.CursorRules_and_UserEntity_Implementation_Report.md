## MagicSquare_23 — Cursor Rules 적용 및 User(Entity) 구현 보고서

작성 목적: `.cursorrules`에 정의된 규칙(ECB, TDD, pytest/AAA, 타입힌트/도큐먼트 규칙)을 기준으로 현재까지 수행한 작업 결과를 기록한다.

---

### 1. 생성/갱신된 규칙 파일

- `.cursorrules`
  - ECB(boundary/control/entity) 레이어 정의 및 의존성 방향 명시
  - TDD 규칙(RED/GREEN/REFACTOR) 단계별 description/rules/must_not 정의
  - pytest + AAA, 커버리지 최소치, fixture scope 규칙 정의
  - 금지 규칙(forbidden): `print(...)`, 매직 넘버/하드코딩 상수, `bare except`
  - AI 행동 규칙(ai_behavior): 테스트 확인, 레이어 경계 위반 금지, 타입힌트 강제, TDD 위반 경고

---

### 2. ECB 폴더/패키지 스켈레톤 생성

ECB 구조에 맞춰 아래 패키지 파일을 생성했다.

- `src/magicsquare/__init__.py`
- `src/magicsquare/boundary/__init__.py`
- `src/magicsquare/control/__init__.py`
- `src/magicsquare/entity/__init__.py`

---

### 3. User 엔티티(Entity 레이어) 구현

목표: 외부 I/O(boundary), 유스케이스(control)와 분리된 **도메인 엔티티(entity)** 로서 `User` 클래스를 작성한다.

- 구현 파일: `src/magicsquare/entity/user.py`
- 핵심 규칙
  - `User.name`은 trim 후 공백/빈 문자열이면 생성 불가(`ValueError`)
  - 엔티티는 불변(immutable)로 두고, 이름 변경은 새 인스턴스 반환(`rename`)
  - 타입힌트 필수
  - Google 스타일 docstring 사용

---

### 4. pytest 테스트(AAA 패턴) 작성

목표: RED→GREEN 원칙에 따라, 구현 전 테스트로 규칙을 고정한다.

- 테스트 파일: `tests/entity/test_user.py`
- 포함 케이스
  - 정상 생성
  - 공백/빈 이름 거부(parametrize)
  - rename이 새 인스턴스를 반환하고 원본이 유지됨(불변성)
  - rename의 공백/빈 이름 거부

---

### 5. 테스트 실행 및 결과

PowerShell 환경에서 `pytest` 실행 파일이 PATH에 없어도 실행되도록, 아래 방식으로 실행했다.

- 실행 커맨드: `python -m pytest`
- 결과: `6 passed`

---

### 6. 테스트 import 경로 설정

`tests`에서 `src` 패키지를 import 할 수 있도록 `pyproject.toml`에 pytest 설정을 추가했다.

- 파일: `pyproject.toml`
- 설정 요약
  - `testpaths = ["tests"]`
  - `pythonpath = ["src"]`
