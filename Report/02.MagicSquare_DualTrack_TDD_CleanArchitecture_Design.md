## Magic Square (4×4) — Dual-Track TDD · Clean Architecture 설계서

프로젝트 목적: 알고리즘 난이도보다 **레이어 분리 + 계약 기반 테스트 + 리팩토링** 훈련  
제약: **구현 코드 작성 금지**, UI는 화면이 아닌 **입력/출력 경계(Boundary)**, Data는 DB가 아닌 **저장/로드 인터페이스**

---

### 고정 입·출력 계약 (변경 금지)

| 항목 | 고정 값 |
|------|---------|
| 입력 타입 | `4x4 int[][]` |
| 빈칸 표기 | `0` |
| 빈칸 개수 | 정확히 **2** |
| 값 범위 | `0` 또는 `1~16` |
| 중복 | `0` 제외 중복 **금지** |
| 출력 타입 | `int[6]` |
| 좌표 | **1-index** |
| 반환 형식 | `[r1,c1,n1,r2,c2,n2]` |
| n1,n2 규칙 | 두 누락 숫자이며, **(작은수→첫빈칸, 큰수→둘째빈칸)** 조합이 마방진이면 그 순서로, 아니면 반대로 |

**빈칸 순서 정의(전 레이어 공통):** 행 1→4, 열 1→4 순으로 스캔하며 처음 만난 `0` = **첫 빈칸**, 그다음 `0` = **둘째 빈칸**.

**마방 상수:** 34  
**검증 선:** 행 4 + 열 4 + 대각선 2 = 10개

# 1) Logic Layer (Domain Layer) 설계

## 1.1 도메인 개념

| 유형 | 이름 | 책임 (SRP) |
|------|------|------------|
| Value Object | `Grid4x4` | 4×4 정수 격자 보유; 불변; 인덱스 접근 |
| Value Object | `CellCoordinate` | `(row,col)` 1-index; 유효 범위(1~4) 보장 |
| Value Object | `EmptyCellPair` | 첫·둘째 빈칸 좌표 쌍; 스캔 규칙으로만 생성 |
| Value Object | `FilledCellSet` | 0이 아닌 칸 값 집합(중복/범위 검증에 사용) |
| Value Object | `MissingNumberPair` | 누락된 두 수 `(min,max)`; `min<max` 보장 |
| Value Object | `MagicConstant` | 상수 34 |
| Value Object | `LineSumSet` | 10개 선의 합들(동일성/상수 일치 판단) |
| Value Object | `SolutionVector` | `[r1,c1,n1,r2,c2,n2]` 도메인 표현 |
| Domain Service | `EmptyCellLocator` | 격자에서 빈칸 2개 탐색 → `EmptyCellPair` |
| Domain Service | `MissingNumberFinder` | 누락 2수 계산 → `MissingNumberPair` |
| Domain Service | `MagicSquareValidator` | 완성 격자에 대해 마방진 불변식 검증 |
| Domain Service | `PartialGridCompleter` | 두 빈칸에 두 수 대입해 완성 격자 생성 |
| Domain Service | `PartialMagicSquareSolver` | 두 조합 시도·유효 조합 선택·`SolutionVector` 생성 |

> Entity 없음: 수명 주기/식별이 필요한 상태 객체가 없으며 VO+Service로 충분.

## 1.2 도메인 불변조건(Invariants)

| ID | 불변조건 | 검증 가능 조건 |
|----|----------|----------------|
| D-STRUCT | 격자는 4×4 | `rows==4 && cols==4` |
| D-EMPTY-COUNT | `0` 정확히 2개 | `count(0)==2` |
| D-VALUE-RANGE | 각 칸 ∈ `{0}∪[1,16]` | 모든 원소 검사 |
| D-NO-DUP-NONZERO | 0 제외 값 중복 없음 | 집합 크기 = 비영 개수 |
| D-MISSING-PAIR | 누락 수 2개 | `{1..16} \ filled` 크기 2 |
| D-COMPLETE | 완성 격자: 0 없음 | `count(0)==0` |
| D-UNIQUE-1-16 | 완성 시 1~16 각 1회 | 집합 크기 16 |
| D-LINE-SUM | 10선 합 동일 | `distinct(sum[10]).size==1` |
| D-MAGIC-CONST | 공통 합=34 | `sum==34` |
| D-ORDER-RULE | 작은수→첫칸 우선, 실패 시 반전 | 두 완성 격자 각각 판정 |
| D-DETERMINISM | 동일 입력 → 동일 출력 | 반복 실행 동일성 |
| D-NO-MUTATE-INPUT | 입력 격자 변경 금지 | 호출 전후 스냅샷 비교 |

**선 정의(합 계산 대상):**

| 선 ID | 정의 |
|-------|------|
| R1~R4 | 행 i(1..4), 열 1..4 |
| C1~C4 | 열 j(1..4), 행 1..4 |
| D1 | (1,1)-(4,4) |
| D2 | (1,4)-(4,1) |

## 1.3 핵심 유스케이스(도메인 관점)

| UC-ID | 이름 | 전제 | 결과 |
|-------|------|------|------|
| UC-D1 | 빈칸 찾기 | D-STRUCT, D-EMPTY-COUNT | `EmptyCellPair` |
| UC-D2 | 누락 숫자 찾기 | D-VALUE-RANGE, D-NO-DUP-NONZERO | `MissingNumberPair(min,max)` |
| UC-D3 | 마방진 판정(완성) | D-COMPLETE, D-UNIQUE-1-16 | `valid/invalid` |
| UC-D4 | 조합 A 시도 | `min→첫빈칸, max→둘째` | UC-D3 |
| UC-D5 | 조합 B 시도 | `max→첫빈칸, min→둘째` | UC-D3 |
| UC-D6 | 해 결정/벡터 생성 | UC-D4~D5 | `SolutionVector` |
| UC-D7 | 부분 격자 해결 | UC-D1~D6 파이프라인 | `SolutionVector` |

**UC-D6 선택 규칙(모호성 금지):**

- 조합 A가 마방진이면 **조합 A** 출력
- 아니고 조합 B가 마방진이면 **조합 B** 출력
- 둘 다 마방진이면 **조합 A 우선**
- 둘 다 아니면 **도메인 실패(UNSOLVABLE)** 처리

## 1.4 Domain API(내부 계약)

> 구현 코드는 작성하지 않고, 메서드 시그니처 수준으로만 고정.

| API | 입력 | 출력 | 실패조건 |
|-----|------|------|----------|
| `Grid4x4 fromRaw(int[][] raw)` | raw | `Grid4x4` | null, 4×4 아님, jagged |
| `EmptyCellPair locateEmpties(Grid4x4 grid)` | grid | `EmptyCellPair` | `count(0)≠2` |
| `MissingNumberPair findMissing(Grid4x4 grid)` | grid | `MissingNumberPair` | 범위 위반/중복 |
| `Grid4x4 complete(Grid4x4 partial, EmptyCellPair cells, int nFirst, int nSecond)` | partial, cells, 두 값 | `Grid4x4` | 값 범위/충돌 |
| `ValidationResult validateComplete(Grid4x4 complete)` | 완성 격자 | `ValidationResult` | 0 존재/중복/합 불일치/34 아님 |
| `SolutionVector solve(Grid4x4 partial)` | 부분 격자 | `SolutionVector` | 둘 다 실패 시 `UnsolvablePartialGridException` |
| `int[] toOutputArray(SolutionVector v)` | v | `int[6]` | - |

**`ValidationResult` 최소 필드:**

| 필드 | 타입 | 설명 |
|------|------|------|
| `valid` | boolean | true/false |
| `violationCode` | enum? | `NOT_COMPLETE`, `DUPLICATE`, `SUM_MISMATCH`, `WRONG_CONSTANT` |

## 2.2 UI 계약(외부 계약)

### Input schema

| 규칙 | 위반 코드 |
|------|----------|
| 입력 null 금지 | `NULL_INPUT` |
| 행 개수 4 | `INVALID_ROW_COUNT` |
| 모든 행 열 개수 4 | `INVALID_COL_COUNT` |
| 빈칸(0) 정확히 2개 | `INVALID_EMPTY_COUNT` |
| 값은 0 또는 1~16 | `OUT_OF_RANGE` |
| 0 제외 중복 금지 | `DUPLICATE_VALUE` |

### Output schema(성공)

- `int[6]`이며 인덱스 의미는 `[r1,c1,n1,r2,c2,n2]`
- `r1,c1,r2,c2 ∈ [1,4]`
- `n1,n2 ∈ [1,16]` 및 `n1≠n2`

### Error schema

| 필드 | 타입 | 필수 |
|------|------|------|
| `code` | string(enum) | Y |
| `message` | string(고정) | Y |
| `details` | map? | N |
