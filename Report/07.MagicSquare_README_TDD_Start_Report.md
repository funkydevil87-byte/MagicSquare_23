## 1. 작성 목적

본 보고서는 Magic Square 4×4 TDD Practice 프로젝트의 **구현 전 README.md 초안**을 작성한 세션 결과를 기록한다. README는 단순 소개 문서가 아니라, PRD 요약 기반 **TDD 시작 선언문**이며 Scenario → Acceptance Criteria → RED Test ID → Test Skeleton → RED Failure → GREEN Task → REFACTOR Candidate 추적 구조를 고정한다.

본 세션에서는 **구현 코드·테스트 코드·파일 생성/수정을 수행하지 않았다.** README Markdown 본문만 채팅으로 출력했다.

### 2.2 README에 반영된 고정 계약

| 항목 | 고정 값 |
|------|---------|
| 입력 | `4×4 int[][]`, `0`=빈칸, 빈칸 2개, 값 `0` 또는 `1~16`, 0 제외 중복 금지 |
| 출력 | `int[6]` = `[r1,c1,n1,r2,c2,n2]`, 좌표 **1-index** |
| Attempt 1 | 작은 누락 숫자 → 첫 빈칸, 큰 누락 숫자 → 둘째 빈칸 |
| Attempt 2 | Attempt 1 실패 시 반대 조합 |
| 마방 상수 | **34** (행4 + 열4 + 대각2 = 10선) |
| 첫 빈칸 | row-major(행 우선) 스캔 시 처음 발견되는 `0` |
| RED 정의 | Test Skeleton 실행 후 **기대한 이유로 실패하는 상태를 확인**하는 단계 |
| GREEN 정의 | RED 실패를 통과시키기 위한 **최소 구현 작업 후보** (본 README에서 수행하지 않음) |
| REFACTOR 정의 | GREEN 이후 **구조 개선 후보** (본 README에서 수행하지 않음) |

## 3. 세션에서 확정한 TDD 원칙

| 원칙 | README 반영 |
|------|-------------|
| RED = 실패 확인 | §1, §3에서 “테스트 실행 → FAIL/ERROR 확인”으로 명시 |
| GREEN = 최소 구현 후보 | Tracking Board `GREEN Task Candidate` 열에만 기록, 수행하지 않음 |
| REFACTOR = 구조 개선 후보 | Tracking Board `REFACTOR Candidate` 열에만 기록, 수행하지 않음 |
| 구현/테스트 코드 금지 | §7 Checklist, §10 Status에 명시 |
| 입출력 계약 변경 금지 | §2, §8 Quality Gates |
