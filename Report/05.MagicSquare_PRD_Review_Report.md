## 1. 작성 목적

본 보고서는 Magic Square 4×4 TDD Practice 프로젝트의 **구현 전 PRD**를 작성한 뒤, 7개 품질 기준으로 검토한 결과를 기록한다. PRD 본문은 `docs/PRD_MagicSquare.md`에 저장되어 있으며, **v1.1**에서 본 보고서 섹션 4(P0~P3) 개선 권고를 반영했다. 본 문서는 **세션 결과 요약**, **검토 발견 사항**, **갱신 이력**을 담는다.

## 2. PRD 작성 세션 요약

### 2.1 입력 및 근거 문서

| 우선순위 | 요청 경로 | 실제 리포지토리 경로 | 상태 |
|----------|-----------|----------------------|------|
| 문제 정의 | `Report/1.ProblemDefinition_Report.md` | `Report/01.MagicSquare_ProblemDefinition_Report.md` | 사용 |
| User Journey | `Report/4.UserJourney_Epic_to_TechnicalScenario_Report.md` | **없음** | Decision Needed (DQ-01) |

| 품질/규칙 | `Report/3.DevelopmentEnvironment_CursorRules_ECB_UserEntity_Report.md` | `Report/03.CursorRules_and_UserEntity_Implementation_Report.md` | 사용 |
| Cursor Rules | `.cursorrules`, `.cursor/rules/*.mdc` | 동일 | 사용 |

### 2.2 PRD에 반영된 고정 계약

| 항목 | 고정 값 |
|------|---------|
| 입력 | `4x4 int[][]`, `0`=빈칸, 빈칸 2개, 값 `0` 또는 `1~16`, 0 제외 중복 금지 |
| 출력 | `int[6]` = `[r1,c1,n1,r2,c2,n2]`, 좌표 **1-index** |
| Attempt 1 | 작은 누락 숫자 → 첫 빈칸, 큰 누락 숫자 → 둘째 빈칸 |
| Attempt 2 | Attempt 1 실패 시 반대 조합 |
| 마방 상수 | **34** (10개 선: 행4+열4+대각2) |
| 첫 빈칸 | row-major(행 우선) 스캔 시 처음 발견되는 `0` |

### 2.3 PRD 구조 (23개 섹션)

Executive Summary → Background → Problem Statement → Why Now → Target Users → Vision → Persona → User Journey → Scope → FR-01~05 → Business Rules → I/O Contract → Error Policy → NFR → Dual-Track TDD → Test Plan → Architecture → Components → Risks → Engineering Principles → Traceability Matrix → Open Questions → Appendix

### 2.4 PRD에서 확정한 실패 정책

- **성공**: `int[6]` 반환
- **실패**: 정의된 Error Code + Message를 포함하는 **예외(throw)**
- **입력 검증 실패**: Domain resolver **미호출**
- **두 조합 모두 실패**: `UNSOLVABLE` + Message `주어진 배치로는 마방진을 완성할 수 없습니다`

### 2.5 PRD Open Questions (작성 시점)

| ID | 내용 |
|----|------|
| DQ-01 | User Journey 1차 근거 문서 부재 |
| DQ-02 | Data Layer 포함 여부 (Report/02 vs PRD Out-of-Scope 충돌) |
| DQ-03 | 실패 신호 방식 — 섹션 13에서 예외로 확정했으나 Open Questions에 미정으로 잔존 (**내부 모순**) |

| # | 기준 | 판정 |
|---|------|------|
| 1 | 모든 FR에 테스트 가능한 AC | **△** |
| 2 | 모든 AC가 Traceability Matrix 연결 | **△** |

---

### 3.2 기준 1 — 모든 FR에 테스트 가능한 AC

**판정: 부분 충족**

| FR | 상태 | 문제 | 개선안 |
|----|------|------|--------|
| FR-01 | △ | `NULL_INPUT`, Message 완전 일치, jagged 구분 AC 없음 | Error Code별 AC 1:1 추가 (예: `AC-FR01-03`) |
| FR-02 | ○ | `AC-FR02-01`, `AC-FR02-02` 검증 가능 | — |
| FR-03 | ○ | `AC-FR03-01`, `AC-FR03-02` 검증 가능 | — |
| FR-04 | △ | 완성 격자 전제(0 없음, 1~16 각 1회) AC 없음 | `AC-FR04-03` 추가 |
| FR-05 | △ | 두 조합 모두 **유효** 시 Attempt 1 우선 규칙 AC 없음 | `Report/02` UC-D6 반영 → `AC-FR05-05` |

**추가 공백**

- `NULL_INPUT`: 계약 표(12.1)에는 있으나 섹션 13 Failure Cases 및 AC 미연결
- NFR(입력 불변, 50ms, 결정성)에 대응 AC 없음

---

### 3.3 기준 2 — 모든 AC가 Traceability Matrix 연결

**판정: 부분 충족**

- 기재된 AC ID 12개(`AC-FR01-01` ~ `AC-FR05-04`)는 Matrix에 등장함
- Matrix → 요구사항 역방향 공백 존재

| 문제 | 개선안 |
|------|--------|
| `UNSOLVABLE` Matrix 행 없음 | Concept 행 추가, FR-05 AC 연결 |
| `BR-02`, `BR-07` Matrix 미연결 | Concept/Invariant 행 추가 |
| `NS`/`ES`/`BS`/`TD` ID Matrix 미연결 | Test Case Candidate 열에 일괄 매핑 |
| DQ-03: 섹션 13 확정 vs Open Questions 미정 | DQ-03 정리 또는 “확정됨” 갱신 |

---

### 3.4 기준 3 — Boundary/Domain 책임 분리

**판정: 부분 위반**

| 위치 | 문제 | 개선안 |
|------|------|--------|
| FR-05 Layer | Control + Domain + Boundary 혼합 | FR 분리 또는 Layer 단일 값 고정 |
| `ResultFormatter` | Layer `Boundary/Control` 이중 표기 | 단일 Layer 확정 |
| `Solver` | Layer `Control/Domain` 이중 표기 | Attempt=Domain, 순서=Control |
| FR-02 vs Report/02 | PRD는 Boundary-only 전제, Report/02는 Domain 방어 검증(D-T10~13) | Domain 방어 검증 포함/제외 명시 |
| UNSOLVABLE | Domain throw vs Boundary 매핑 주체 불명확 | 예외 계층 및 매핑 책임 1문단 확정 |

**양호**: “입력 검증 실패 시 Domain 미호출”은 FR-01, 섹션 13, Track A에 일관됨

---

### 3.5 기준 4 — 오류 정책 미정 없음

**판정: 대체로 확정, 세부 공백·모순 있음**

| 항목 | 상태 | 개선안 |
|------|------|--------|
| 실패 신호 | 섹션 13=예외 vs DQ-03=미정 | **문서 내부 모순** 해소 |
| `NULL_INPUT` | 13.1 Failure Cases表 누락 | 행 추가 |
| Domain vs Boundary 예외 | 미정 | 예외 계층·매핑 규칙 추가 |
| both-valid (둘 다 마방진) | `Report/02` UC-D6 “조합 A 우선” PRD 누락 | BR + AC + NS-03 추가 |
| 성공 계약 위반 | “버그”만 기술 | invariant assertion 정책 1줄 확정 |

---

### 3.6 기준 5 — small-first vs reverse 테스트 데이터 구분

**판정: 조건 수준 구분, fixture 수준 미구분**

- `TD-01`(Attempt 1만 성공), `TD-02`(Attempt 1 실패 후 Attempt 2 성공) 조건 분리됨
- `NS-01`, `NS-02`, Gherkin 2시나리오 분리됨
- **문제**: 16.4에서 “구체 행렬 미포함” 명시 → 실행 가능 fixture 없음, 혼동 방지 약함
- **개선안**: Appendix에 대표 행렬 1쌍 또는 “Attempt 1 valid=false/true” 필수 속성 표 추가

---

### 3.7 기준 6 — 1-index·row-major 규칙

**판정: 대체로 포함, Traceability·AC 보강 여지**

- BR-06, BR-14, BR-15, FR-02, Matrix `row-major`/`1-index` 행 존재
- **누락**: BR-07(둘째 빈칸) Matrix 행 없음; 출력 좌표=탐색 결과 동일 AC 없음

---

### 3.8 기준 7 — 구현/테스트 코드 미포함

**판정: 충족**

- 실행 가능한 Python/pytest 코드 없음
- Gherkin·Test ID는 설계 식별자 수준
