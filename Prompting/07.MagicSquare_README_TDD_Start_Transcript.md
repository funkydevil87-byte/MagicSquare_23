프로젝트:
MagicSquare 4x4 TDD Practice

README.md에 반드시 포함할 핵심 흐름:
1. Scenario 정의
2. Acceptance Criteria 정의
3. RED Test ID 부여
4. Test Skeleton 작성
5. 테스트 실행
6. 실패 확인 = RED
7. 그 실패를 통과시키는 최소 구현 = GREEN
8. 구조 개선 = REFACTOR

도메인 규칙:
- 입력은 4x4 int 행렬입니다.
- 0은 빈칸입니다.
- 빈칸은 정확히 2개입니다.
- 값은 0 또는 1~16입니다.
- 0을 제외한 중복 숫자는 허용되지 않습니다.
- 4x4 마방진 상수는 34입니다.
- 출력은 int[6]입니다.
- 출력 좌표는 1-index 기준입니다.
- 출력 형식은 [r1, c1, n1, r2, c2, n2]입니다.
- 첫 번째 빈칸은 row-major 순서로 처음 발견되는 0입니다.
- 먼저 작은 누락 숫자를 첫 번째 빈칸에, 큰 누락 숫자를 두 번째 빈칸에 넣습니다.
- 첫 번째 시도가 실패하면 반대 조합을 시도합니다.

적용 방법론:
- Concept-to-Code Traceability
- Dual-Track UI + Logic TDD
- ECB, Entity / Control / Boundary
- RED → GREEN → REFACTOR
- Scenario → Acceptance Criteria → RED Test ID → Test Skeleton → RED Failure → GREEN Task → REFACTOR Candidate 추적
